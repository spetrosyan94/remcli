# Бриф для Claude Design — remcli web

> Скопируй текст ниже целиком в Claude Design. Результат сохранить по структуре из раздела «Формат передачи» в конце.

---

Спроектируй современный, лаконичный и эргономичный дизайн веб-приложения **remcli** — мобильного пульта управления AI-агентами для разработчиков.

## Что за продукт

remcli — это веб-клиент, через который разработчик со смартфона (или десктопа) управляет AI-кодинг-агентами (Claude Code, OpenAI Codex, Google Gemini, Cursor), запущенными на его компьютере. Всё работает P2P: на компьютере крутится локальный демон-сервер, телефон подключается к нему напрямую по QR-коду (LAN или туннель), весь трафик E2E-зашифрован. Облака и аккаунтов НЕТ — подключение по QR и есть «логин». Пользователь — разработчик: он отходит от компьютера, а с телефона видит, что делает агент, отвечает на его вопросы, разрешает/запрещает действия, диктует задачи голосом и слушает ответы озвучкой.

Характер бренда: инструмент разработчика, терминальная эстетика, надёжность, приватность («ваш компьютер и есть сервер»). Без корпоративной стерильности и без игрушечности.

## Ключевые требования

1. **Mobile-first, приоритет — iPhone**. Приложение добавляется на домашний экран («Add to Home Screen») и должно ощущаться как полноценное нативное приложение в standalone-режиме:
   - никакой опоры на браузерный хром: своя навигация, свои кнопки «назад»;
   - safe areas (чёлка/Dynamic Island сверху, home-индикатор снизу) — контент и нижняя навигация учитывают отступы;
   - высота 100dvh, никаких «прыжков» от адресной строки;
   - тач-цели минимум 44×44pt, нижняя навигация/основные действия — в зоне большого пальца;
   - продумай theme-color строки состояния и splash-экран.
2. **Дизайн строится на shadcn/ui** (Radix + Tailwind): используй только компоненты и паттерны, реализуемые через shadcn (Button, Card, Sheet, Drawer, Dialog, DropdownMenu, Tabs, Badge, Command, Sonner-тосты, Skeleton и т.д.). Никаких экзотических кастомных контролов без необходимости.
3. **Тёмная тема — основная** (разработчики, терминал), светлая — обязательная альтернатива. Палитра: нейтральная база (zinc/slate) + один спокойный акцент; статусные цвета для состояний агентов. UI-шрифт — Inter или Geist; моноширинный (JetBrains Mono / Geist Mono) — для кода, путей, имён сессий, терминала: моно-акценты — часть идентичности.
4. **Лаконичность**: минимум хрома, максимум содержимому чата. Плотность информации как у хорошего dev-инструмента, а не как у мессенджера для подростков.
5. **Десктоп-вариант** — вторичен, но нужен: колоночный layout (сайдбар со списком сессий + чат), для остальных экранов достаточно адаптива.

## Экраны (для каждого: мобильный 390×844 обязателен, тёмная тема обязательна; светлая и десктоп — минимум для Home и Chat)

1. **Onboarding / Подключение** — первый запуск: краткое ценностное обещание, кнопка «Сканировать QR» (камера), альтернатива — ручной ввод адреса+ключа; состояние «подключаемся…» и ошибка подключения. Это единственный «маркетинговый» экран.
2. **Home / Сессии** — список машин (компьютеров) и их сессий: имя проекта/директории (моно), агент (иконка Claude/Codex/Gemini/Cursor), статус (работает/думает/ждёт разрешения/ожидает/офлайн — цветовая система статусов), последнее сообщение. Свайп/меню для остановки. FAB или заметная кнопка «Новая сессия». Пустое состояние. Индикатор соединения с демоном.
3. **Новая сессия** — пошаговый выбор: машина → агент (4 карточки) → модель → режим разрешений (safe/ask/auto) → рабочая директория (недавние + ввод) → или «продолжить прошлую сессию» (resume-пикер со списком прошлых сессий агента с датами). Должно решаться в 2-3 тапа для повторного сценария.
4. **Чат сессии — ГЛАВНЫЙ ЭКРАН, максимум внимания**:
   - шапка: проект (моно), агент+модель, статус, переключатель режима разрешений, меню;
   - лента: сообщения пользователя и агента (markdown, код с подсветкой), сворачиваемые карточки tool-вызовов (Read/Edit/Bash…) с параметрами, диффы файлов (+/− строки), результаты;
   - **карточка запроса разрешения** — самый важный элемент: агент просит разрешение выполнить команду/правку, крупные кнопки Разрешить/Запретить (+«всегда разрешать»), видно ЧТО именно он хочет сделать; должна быть заметна мгновенно;
   - статус «агент думает/пишет» (стриминг);
   - у сообщений агента — кнопка «Слушать» (TTS: состояния синтез→играет→стоп);
   - поле ввода: текст + кнопка диктовки (запись голоса: анимация уровня, таймер, стоп → «распознаём…»), отправка;
   - состояния: подключение потеряно/восстановление, сессия завершена.
5. **Терминал** — просмотр вывода терминала сессии (моно, тёмный всегда), ввод команды.
6. **Zen-режим** — минималистичный список задач, привязанных к сессиям: добавить задачу, «работать над задачей» (запускает агента), связанные сессии. Самый тихий и чистый экран.
7. **Настройки** — тема, язык (10 языков), голос: провайдер TTS и голос, управление машинами (переименовать/удалить, добавить по QR), о приложении. Сгруппированные списки.
8. **Command Palette** (⌘K / кнопка) — быстрый переход по сессиям и действиям.

## Логотип и айдентика — СОЗДАТЬ ПОЛНОСТЬЮ С НУЛЯ

Текущий логотип отправляется в утиль, не опирайся на него ни в чём. Что сейчас и почему не годится: жирная округлая брусковая (slab-serif) буква «R» терракотово-оранжевого цвета — выглядит как логотип детского издательства, никак не передаёт суть (удалённый пульт AI-агентов, терминал, P2P, шифрование) и не сочетается с современным лаконичным UI.

Требования к новому знаку:
- **Дай 3 разных концепта** знака на выбор, каждый — с коротким обоснованием. Возможные направления (не ограничивайся ими): терминальный prompt «>» или «>_» со смысловым твистом дистанционности/сигнала; монограмма «r» в техно-геометричном построении; узел P2P-связи «телефон ↔ компьютер»; курсор-каретка. Строго без: маскотов, градиент-мыла, скруглённо-мультяшных букв, генеричных «AI-искр».
- **Геометрия**: строится на сетке, читается в 16-24px (favicon!), уверенно работает одноцветным.
- **Характер**: инженерный, точный, спокойный; терминальная эстетика; уместен рядом с иконками GitHub/VS Code/Linear на домашнем экране разработчика.
- **Wordmark**: «remcli» строчными, моноширинный или техно-гротеск, сбалансирован со знаком.
- **Комплект для выбранного концепта**: иконка iOS home screen (maskable, тёмный и светлый вариант фона), favicon, монохромная версия, splash-заставка, анимация знака (см. раздел «Анимации»).
- Покажи знак в контексте: иконка на домашнем экране iPhone рядом с нативными приложениями; шапка приложения; splash.

## Дизайн-система / UI-kit (отдельный обязательный артефакт)

Помимо экранов создай **единый лист дизайн-системы** (styleguide, один экран-полотно в тёмной и светлой теме), из которого можно собрать любой экран приложения:

1. **Фундамент**: семантические цвета (фоны/поверхности/бордеры/текст, primary, destructive) + статусная палитра агентов (running / thinking / waiting-permission / idle / offline / error); типографическая шкала (UI + mono); шкала отступов; радиусы; тени/elevation (минимальные).
2. **Базовые shadcn-компоненты** — только выбранные варианты и размеры, которые используются в приложении (Button: варианты и размеры; Input; Badge; Card; Tabs; Sheet/Drawer; Dialog; Switch; Select; Skeleton; Toast) — не все подряд, а курируемый набор.
3. **Прикладные композитные компоненты remcli во ВСЕХ состояниях** — это самое ценное:
   - **StatusBadge/StatusDot** — 6 статусов агента (цвет+иконка+подпись);
   - **AgentIcon** — иконки/маркировка четырёх агентов (Claude/Codex/Gemini/Cursor) в едином стиле;
   - **SessionCard** — элемент списка сессий: обычная / активная / ждёт разрешения / офлайн;
   - **PermissionCard** — запрос разрешения: обычный и опасный (rm, force-push), свёрнутый/развёрнутый, с кнопками Разрешить/Запретить/Всегда;
   - **ToolCallCard** — карточка tool-вызова: свёрнута/развёрнута, running/success/error, с параметрами и результатом;
   - **DiffView** — блок диффа файла (+/− строки, имя файла моно);
   - **ChatMessage** — пользователь / агент / агент-стриминг («думает») / системное;
   - **VoiceRecordBar** — запись (уровень+таймер+стоп) / распознавание / ошибка;
   - **ListenButton (TTS)** — idle / синтез / играет / ошибка;
   - **ConnectionBanner** — потеря/восстановление соединения;
   - **EmptyState** — паттерн пустых состояний (нет сессий, нет машин, нет задач).
4. Все композитные компоненты — в обеих темах, с mobile-шириной 390px.

Экраны из раздела выше должны быть собраны ИЗ этих компонентов (единообразие проверяется именно так).

## Анимации и живость интерфейса (обязательный раздел)

Определи сдержанный анимационный язык приложения (dev-инструмент, не игрушка): длительности/кривые (быстро, 120-250ms, ease-out) и конкретные анимации для ключевых состояний:

1. **«Агент думает»** — фирменная анимация ожидания в чате (не банальные три точки, но и не цирк: например, пульсирующий терминальный курсор или бегущий символ в моно-стиле);
2. **Стриминг ответа** — появление текста и плавный автоскролл;
3. **VoiceRecordBar** — живые бары уровня звука при записи, переход запись→распознавание;
4. **ListenButton (TTS)** — синтез (ожидание) → воспроизведение (эквалайзер) → стоп;
5. **Смена статуса сессии** — плавный переход цвета/точки статуса (idle→running→permission);
6. **PermissionCard** — появление с мягким акцентом (привлечь внимание, не раздражать);
7. **Переходы экранов и Sheet/Drawer** — стандартные для standalone PWA (ощущение нативности);
8. **Skeleton-загрузка** списков и **splash → home** плавный вход;
9. **Анимированная версия логотипа** — короткая (≤1.5s) анимация знака для splash-экрана и пустых состояний (опиши покадрово или дай CSS/SVG-анимацию).

Реализация анимаций должна быть возможна через CSS/Tailwind (tailwindcss-animate) и SVG — без тяжёлых зависимостей; если предлагаешь Lottie — только для splash/логотипа, опционально.

## Что отдать в результате (строго)

1. **Дизайн-токены**: CSS-переменные в формате темы shadcn/ui (light + dark): фоны, foreground, primary, статусные цвета агентов (running/thinking/permission/idle/offline), радиусы, шрифты.
2. **UI-kit кодом**: лист дизайн-системы (см. раздел выше) — отдельный самодостаточный файл (TSX или HTML с Tailwind), обе темы.
3. **Экраны кодом**: каждый экран — самодостаточный React (TSX) или HTML с Tailwind-классами и разметкой в духе shadcn/ui компонентов, собранный из компонентов UI-kit. Мобильная вёрстка 390px; для Home и Chat — также десктоп ≥1024px.
4. **DESIGN.md**: принципы (сетка, отступы, типографическая шкала), навигационная модель (что в нижней навигации, что в Sheet/Drawer), карта состояний статусов, правила анимаций (сдержанные), PWA-детали (theme-color, splash).
5. **Ассеты**: логотип/знак/wordmark в SVG, иконка приложения 1024×1024 PNG + maskable-вариант, favicon SVG; анимация логотипа (CSS/SVG, для splash).
6. **MOTION.md или раздел в DESIGN.md**: спецификация анимаций из раздела «Анимации» (длительности, кривые, покадровое описание или готовый CSS).

# Формат передачи дизайна обратно (инструкция для владельца)

Сложи результат Claude Design в репозиторий так:

```
design/
  DESIGN.md              # спецификация (принципы, навигация, состояния, PWA)
  tokens.css             # CSS-переменные shadcn-темы (light + dark)
  screens/               # по файлу на экран: connect.tsx|html, home.tsx, chat.tsx,
                         #   new-session.tsx, terminal.tsx, zen.tsx, settings.tsx, palette.tsx
  assets/
    logo.svg  logo-mono.svg  wordmark.svg  favicon.svg
    app-icon-1024.png  app-icon-maskable.png  splash.png (опц.)
  screenshots/           # опционально: PNG-превью экранов (тёмная/светлая)
```

- Приоритет формата экранов: **TSX с Tailwind** (лучше всего для переноса) > HTML с Tailwind > статичные PNG (хуже всего — только как референс).
- Если Claude Design выдаёт один большой артефакт — можно одним файлом, я разрежу; главное, чтобы внутри была мобильная вёрстка и токены.
- После выкладки файлов скажи мне «дизайн в design/» — и я запускаю волну 6 (реализация на Vite + React + shadcn/ui строго по этому дизайну).
